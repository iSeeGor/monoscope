# API Contracts

## Conventions

- Base path: `/api/v1`.
- JSON field names use `camelCase`.
- OpenAPI generated by FastAPI is the source of truth.
- Frontend TypeScript types are generated from OpenAPI.
- Dates use `YYYY-MM-DD`; timestamps use ISO 8601 with offset.
- Money and percentages are decimal strings.
- Breaking changes require a new API version.

## Health

`GET /health`

Returns application status without checking or exposing the Monobank token.

```json
{
  "status": "ok",
  "version": "0.1.0"
}
```

## Generate report

`POST /reports`

Request:

```json
{
  "includeBlackCard": false,
  "dateFrom": "2026-09-01",
  "dateTo": "2026-09-30",
  "includeHolds": true
}
```

Validation:

- white-card expenses are always included;
- `includeBlackCard` defaults to `false` and adds black-card expenses when true;
- both dates are required and inclusive;
- `dateFrom` is not after `dateTo`;
- range is no longer than 31 inclusive days;
- future end dates are clamped to the current Kyiv time only when the end date
  is today; later dates are rejected.

## Export completed report

- `GET /reports/{reportId}/export.csv`
- `GET /reports/{reportId}/export.md`

Exports read the completed cached report and do not call upstream APIs.
Responses use a UTF-8 attachment filename derived from the report period.

CSV columns remain compatible with the existing CLI:

```text
date,time,description,comment,category,mcc,amount_original,
currency_original,amount_eur,rate_used,rate_source,hold,id,card_type
```

`amount_uah` may be appended as a new column after `amount_eur`; existing
columns must not be renamed silently.

## Errors

All handled errors use:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Date range must not exceed 31 days.",
    "requestId": "...",
    "details": {
      "field": "dateTo"
    }
  }
}
```

Expected status mapping:

- `401 MONOBANK_UNAUTHORIZED` for an invalid configured token;
- `404 REPORT_NOT_FOUND` for an unknown or expired export report;
- `422 REQUEST_SCHEMA_INVALID` for malformed fields or invalid date ranges;
- `429 MONOBANK_RATE_LIMITED` for upstream request limits;
- `502 MONOBANK_UNAVAILABLE` for upstream failures;
- `500 INTERNAL_ERROR` for unexpected failures.

Details are optional and must never include secrets or raw upstream payloads.

## Contract evolution

Additive response fields are allowed within v1. Fields may not change meaning
or type. UI code must consume generated types and use mapping functions at the
entity boundary rather than passing transport objects through every component.
